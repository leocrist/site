# Implementation playbooks

Choose the matching section; combine only for requested multi-asset work. Use the relevant production skill and tools for actual file creation.

## Website / landing page
1. Establish audience, message and action; map required content to sections.
2. Research full-page composition in Land-book; add hero/navigation/pricing/proof sources only for those actual needs.
3. Define grid, tokens and reusable components. Build semantic responsive content with actual copy.
4. Implement functional navigation, links, forms and states appropriate to scope. Clearly distinguish simulated behaviour from real submission.
5. Preview narrow and wide layouts, keyboard focus, content overflow and actual links. Follow Sites instructions for packaging/hosting and the user's access constraints.

## Hero section
1. Identify what must be understood at first glance; preserve long or technical titles accurately.
2. Compare 1–2 suitable hero compositions in Supahero; use Land-book to fit surrounding page.
3. Arrange headline, support, primary/secondary CTA if relevant, and focal image without crowding.
4. Implement desktop/mobile compositions; verify wrapping and image cropping. Do not add CTA to a purely informational cover without purpose.

## Pricing
1. Obtain or preserve actual packages, billing units, currency, taxes/conditions where supplied, and selection criteria. Do not fabricate missing commercial terms.
2. Match subscription/one-off/usage/contact-sales structure in Pricing Pages.
3. Build cards/table with explicit differences, consistent feature terminology and accessible controls.
4. Test month/year values and calculator logic against supplied rules. If no rules exist, show labelled placeholders rather than working-looking false calculations.
5. Verify mobile reading order, feature availability and billing clarity.

## Social proof / trust
1. Identify the claim and reader objection; inventory verified evidence.
2. Match a pattern in Social Proof Examples.
3. Present attribution, context and relevant outcomes beside supported claims.
4. Use real permissions/approved logos and exact quotations where provided. If no evidence exists, omit the unsupported claim or use a clearly labelled slot.
5. Verify numbers and attribution; do not exaggerate generalisability.

## Presentation
1. Inspect source material and audience/time limit; map a narrative before decorative layouts.
2. Use Deck.gallery Report/Talks for research presentations; Pitch/Sales only when that purpose fits.
3. Build cover, content, section divider, evidence/data and conclusion layouts as needed. For conference work, maintain author names, affiliations, institutional logos and cautious research language.
4. Create editable text/shapes/charts through the Presentations workflow; use raster images for suitable artwork, not an entire editable slide.
5. Check chart axes/units/source notes, equation legibility, Vietnamese glyphs, contrast and title wrapping. Preserve backup slides or notes if requested.
6. Render every slide, repair clipping/overlap and verify pacing against the talk duration.

## Email
1. Establish lifecycle event, recipient needs and primary action; use Really Good Emails category matching that event.
2. Draft subject/preheader when requested, then opening, message, supporting modules, CTA and appropriate footer.
3. Produce requested copy, mockup or email-compatible HTML. Avoid assuming general web CSS works in email clients.
4. Check mobile width, meaningful alt text, links and readable text with images blocked. State if real inbox testing was not available.
5. Deliver the asset; do not send or schedule it without user authorization.

## Social post / event poster / header
1. Establish platform/format, purpose and exact key facts; inspect supplied brand material.
2. Use Posts.design matching category; for an event prioritize title, speaker, date/time, venue and registration information as supplied.
3. Define a readable headline, dominant image/device and secondary details. For a series, create a consistent system with purposeful variation.
4. Produce the required dimensions or specify assumed ones. Keep essential text away from likely crops; verify platform requirements when making exact claims.
5. Inspect at feed size and full size; verify all event details and Vietnamese accents.

## Advertisement
1. Establish audience, channel, awareness stage, offer and action.
2. Use Adfolio primarily for B2B SaaS; use Posts.design or user-specific references for other sectors.
3. Develop hook, visual, benefit/evidence and CTA as one message. Provide alternatives only when requested or needed for open-ended direction selection.
4. Build actual creative in requested sizes and preserve landing-page message continuity if a page is in scope.
5. Verify claims/offer accuracy and small-size legibility. Label performance predictions as hypotheses; do not claim measured conversion uplift.

## Navigation
1. Inventory real destinations and user tasks; group and label them.
2. Choose static/dropdown/mega-menu/sidebar/search/fullscreen based on complexity using Navbar Gallery.
3. Implement desktop/mobile, current state, focus, keyboard support and open/close behaviour. Use semantic links/buttons and meaningful labels.
4. Test overflow, escape/return focus where applicable, touch interaction and broken destinations. Do not infer behaviour from a screenshot.

## Open Graph / link preview
1. Identify page type, title, brand and target sharing platform.
2. Study actual images in OGimage.gallery; define concise title hierarchy and one focal device.
3. Create image with dimensions suited to the target platform; verify current platform specifications when necessary.
4. If implementation includes a website, set relevant metadata and public image URL through the website workflow; an image file alone is not a working preview integration.
5. Preview the crop at small size, verify title/brand and report whether a platform debugger was actually used.

## Revision and multi-asset rules
- Local edit: preserve style and researched direction; inspect only new references necessary for the change.
- Visual audit: capture the actual artifact first; tie each finding to visible evidence and a concrete fix. Use relevant audit skill where available.
- Multi-asset set: establish shared colours, typography, spacing and imagery; adapt information density to each medium. Verify each output independently.
- Exact clone: obey user scope and reference fidelity; avoid imposing this workflow's three-direction exploration.
